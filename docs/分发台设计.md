# 分发台设计（Dispatcher v0.1，2026-10-05）

> 定位：多平台内容分发与监控的工作台。**不绕过任何平台风控**——公众号走官方 API 全自动；知乎/小红书由程序备料，发布键永远用户亲自按；监控用数据回填（不爬虫，规避 ToS 与封号风险）。

## 一、架构

```
正典仓库 docs/（唯一内容源）
   │
   ├─ 适配层：md2html（公众号）｜xhs_cards.py（小红书图卡）｜知乎体改写（人工+检查单）
   │
   ├─ 分发层 tools/dispatcher.py
   │    ├─ wx publish-status   公众号发布/定时状态查询（官方 API）
   │    ├─ wx check            草稿箱乱码/口径核验（隔离实验固化的四绿检查）
   │    ├─ plan                各平台待办看板（从大纲/手册规则生成）
   │    ├─ metrics             数据回填（CSV：各平台发布物+指标），替代爬虫
   │    └─ scoreboard          战绩板到期提醒与登记
   │
   └─ 记录层 data/metrics.csv + data/publish_log.csv（git 版本化，可审计）
```

## 二、各平台自动化边界（与手册红线对齐）

| 平台 | 发布 | 监控 | 原因 |
|------|------|------|------|
| 公众号 | **全自动**（API 灌稿/定时/发表状态） | 全自动（官方数据接口/后台导出） | 唯一开放 API 的平台 |
| 知乎 | 程序出底稿→人贴入存草稿→人按发布 | 手动回填（赞同/收藏） | 无个人 API；模拟操作=封号风险 |
| 小红书 | 程序出卡片→人上传→人按发布 | 手动回填（收藏率/搜索命中） | 同上，且 2026-03 导流细则风控更严 |
| 星球/小报童 | 1k 粉后接入 | — | 变现后置 |

## 三、数据规范

**data/publish_log.csv**：`date,platform,title,item_ref,status(草稿/已发布/定时),note`
**data/metrics.csv**：`date,platform,title,metric,value`（metric：赞/藏/评/阅读/涨粉/导流回读）
**核对纪律**：回填数据每周日一次，10 分钟内完成；月度复盘时 dispatcher 汇总。

## 四、后续可扩展（不承诺）

- 公众号官方数据统计接口（发布的第 2 天起有阅读数据，可接入 wx metrics 自动抓取）
- 知乎/小红书若未来开放接口则升级
- **明确不做**：浏览器脚本模拟登录发内容（风险/收益比最差的一格）
