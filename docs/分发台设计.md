# 分发台设计（Dispatcher v0.6 → 五层架构，2026-10-07）

> 定位：多平台内容分发与监控的工作台。**不绕过任何平台风控**——自动化做到发布键前一格，按键永远归用户。本版将系统重构为五层架构，人只保留两个不可替代的决策点：**定稿**与**异常确认**。

## 一、五层总体架构

```
⑤ 数据回流层：阅读/涨粉/限流信号 → 反哺选题与排期
   ├─ metrics.csv / report / monitor /（v0.7）stats
   └─ 战绩板 + 起号期排期调整（docs/起号期逻辑）
④ 分发执行层：按平台分通道
   ├─ API通道      公众号（wx_api.py，全自动）
   ├─ 浏览器通道   小红书/知乎（prep.py + 灵犀浏览器会话，停在发布键）
   ├─ 人工兜底     星球/小报童/扫码类
   └─ 国际API      telegram/bluesky/devto（flows.post）
③ 内容中心（单一事实源）：正典仓库 docs/*.md 主文件
   ├─ data/content_index.csv 内容索引（状态机）
   ├─ data/queue.csv 排期队列（发布器只认队列，不认临时指令）
   └─ 适配模板：md2html（公众号）/ xhs卡片 / 知乎体改写
② 素材生产层：LLM 初稿 + 人工定稿；一稿多形态拆条
① 调度与进化层：timer_task 定时 + 失败→记录→修复→模板沉淀
```

## 二、各层职责与现状映射

| 层 | 职责 | 现有实现 | 待建 |
|---|---|---|---|
| ① 调度进化 | 定时触发、失败修复沉淀 | timer_task（每日zh-scout等）、发布操作规程文档 | 失败截图→LLM修选择器→成功后沉淀为平台标准模板（v0.8+） |
| ② 素材生产 | LLM初稿+人工定稿+多形态 | 连载母稿、mp_adapt、xhs_cards、封面管线 | 视频脚本形态（后置） |
| ③ 内容中心 | 单一事实源+状态机+排期 | 正典仓库docs母稿、ledger.csv | **content_index.csv + queue.csv（本版落地）** |
| ④ 分发执行 | 按通道发布 | dispatcher.py 13命令 | prep zhihu（养号期满）、stats 自动拉数 |
| ⑤ 数据回流 | 指标统一、反哺排期 | metrics.csv/report/monitor | stats（公众号datacube+知乎API，v0.7） |

## 三、内容中心数据规范（单一事实源）

**母稿**：`docs/*.md` 唯一主文件；平台差异只体现在适配模板产物（docs/素材/、assets/xhs/）。

**data/content_index.csv**：`item,topic,status,note`
状态机：`draft → final(定稿) → scheduled(排期) → publishing(进行中) → published → measured(数据回填)`
规则：任何一步失败**停在原地等人处理，不静默重试**；状态只由命令推进，不手改。

**data/queue.csv**：`date,platform,item,note`
排期队列驱动一切发布动作；`queue due` 输出当日应发布清单，`prep` 只对队列内条目或显式指定稿名执行。

**data/ledger.csv**：执行台账（v0.6 已建）。`pending_publish → published → measured`。

**data/metrics.csv / publish_log.csv**：回流与发布记录（沿用 v0.1 规范）。

## 四、分发执行通道边界（红线对齐）

| 通道 | 平台 | 自动化程度 | 红线 |
|---|---|---|---|
| API | 公众号 | 全自动（灌稿/定时/状态） | IP 白名单 |
| 浏览器 | 小红书、知乎 | prep 预填→停在发布键 | 登录态不出域、不碰验证码、AI标注、术语降敏 |
| 聚合工具 | — | **不引入蚁小二托管** | 账号密码出域=红线；只仿其流程不仿其机制 |
| 人工兜底 | 星球/小报童/扫码类 | 人工 | — |
| 国际API | telegram/bluesky/devto | 全自动 | 凭据入 .env |

## 五、运营原则（防封防限流）

1. **拟人节奏**：每平台每日限频、错峰发布；小红书晚21点后、知乎每周2答
2. **登录态管理**：Cookie 手动刷新，绝不自动化验证码
3. **灰度机制**：新内容先发主平台（公众号），无异常再分发其他端
4. **状态机纪律**：失败停在原地等人；`plan` 看板每日核对
5. **进化闭环**：平台改版 → 失败记录（页面结构/错误信息）→ LLM 修复选择器 → 人确认一次 → 沉淀为该平台标准模板（写回 prep.py 规程）

## 六、落地里程碑

| 阶段 | 内容 | 状态 |
|---|---|---|
| 第1周 | 内容中心建表（content_index+queue）+ 公众号 API | **本版** |
| 第2周 | prep xhs 浏览器通道 + ledger 闭环 | ✅ v0.6 |
| 第3-4周 | prep zhihu + stats 数据回流 + 排期自动调整 | v0.7-v0.8 |
| 之后 | 失败进化机制 + dispatch 全平台串跑 + MCP 化 | v0.9-v1.0 |

**明确不做**：托管登录态自动提交（蚁小二高危20%）、验证码自动化、互赞群、正文导流（知乎/小红书红线）。
