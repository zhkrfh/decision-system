## 一、值得关注的四个项目/趋势

### 1. Postiz（gitroomhq/postiz-app，29k+ stars）——自托管社媒调度器 ★最相关
- **是什么**：开源 Buffer 替代品，一个面板发布到 30+ 平台（X/LinkedIn/Reddit/Bluesky/Mastodon/Pinterest 等），带 AI 辅助生成、可视化日历、分析、**公开 REST API 与 MCP 端点**，自托管零通道费
- **可借鉴**：①它的**平台适配器架构**（每平台一个 provider 插件）是分发台 v1.0 的成熟参照——我们把公众号 provider 写好后，未来任何新平台（若开放 API）只需一个插件；②**MCP 端点**设计：让 AI agent 直接调用排程能力，正是我们 dispatcher 的演进方向
- **局限**：平台列表里没有知乎/小红书（国内平台无 API 是全球性难题），不能直接解决我们的手动发布问题
- **迁移判断**：✅ 架构参考（分发台 v1.1 按 provider 模式重构）；❌ 不直接部署（我们的平台不在其列，自托管多一个运维负担）

### 2. Agent Skills 模块化（openai/skills、anthropics/skills 等）——本周 GitHub 最热趋势
- **是什么**：把提示词、工具调用、权限、业务流程封装成**可组合、版本化、可审计的技能包**；焦点从单体 Agent 转向能力包时代
- **可借鉴**：**我们的发布 SOP、口径核验、四关选题、md2html 管线本身就是"技能包"**——已经以 tools/ + docs/ 散落形态存在。参照 Skills 规范做版本化封装（SKILL.md + 资源 + 权限声明），既方便自己复用，也符合"卖工具"的产品化方向：**算分表工具可以做成标准 Skills 发售**
- **迁移判断**：✅ 中期方向（分发台稳定后，把管线封装为对外可售技能包）

### 3. github/gh-aw（Agentic Workflows，Technical Preview）——直接可用的自动化通道
- **是什么**：用 Markdown 描述 agent 工作流，编译成 GitHub Actions，在仓库语境里跑（带审查、CI、issue 联动）
- **可借鉴**：**独立站的"内容同步"可以走 GitHub Actions**：正典仓库更新 → 触发 action → 跑 build_case.py → push decision-site → Pages 自动重建。目前这步是我手动跑的，Action 化后彻底无人值守
- **迁移判断**：✅ 立即可做（轻量：decision-site 加一个 workflow，或用 Gitee 的 webhook 推送触发）。风险：gh-aw 尚在 preview，先用普通 GitHub Actions 实现同效

### 4. Panniantong/Agent-Reach（+696/日）
- **是什么**：一个 CLI 给 agent 提供对 Twitter/Reddit/YouTube/GitHub 的读取与搜索，无 API 费
- **可借鉴**：**监控层的"数据回填"可以借这类无 API 费通道**，但覆盖不含知乎/小红书；对其抓取合规性需谨慎评估（爬虫 ToS 风险与手册红线同源）
- **迁移判断**：⏸ 观察名单。优先级低于前三个

## 二、行业信号（对定位的印证）

1. **垂直 Agent 落地加速**（金融 AutoHedge、营销 marketingskills）——印证"启迪者"路线里"行业 Agent/工具"的可行性，职业决策垂直工具不是孤例
2. **自托管工作流成本优势**（比 SaaS 省 90%）——印证不依赖第三方 SaaS、自建管线的选型
3. **供应链安全升温**（Skills/MCP 的权限泄露、投毒风险）——我们若对外发售技能包，需提前设计权限声明与签名机制
