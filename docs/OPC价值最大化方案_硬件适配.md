# OPC 价值最大化方案：基于本机实测的可行性边界

> 生成时间：2026-10-10
> 硬件依据：本机实测（4 核 / 3.9 GB 内存 / 独显无算力占用 / E 盘可用 146 GB）
> 定位：轨道二（系统建设），服务于 OPC 一人公司

---

## 一、硬件实测结果与硬约束

| 项 | 实测值 | 判定 |
|---|--------|------|
| CPU | 4 逻辑核 | 中等偏低，多进程调度受限 |
| **物理内存** | **3.9 GB，已用 97%** | 🔴 **最关键约束** |
| 显卡 | 有独显，无 CUDA 进程占用 | 驱动在，非算力可用 |
| 磁盘 | E 盘可用 146 GB，C 盘仅 12.4 GB | E 盘充裕 |
| 网络 | GitHub 200(0.8s)、小红书 200(0.5s)、微信/知乎 4xx（凭证问题） | 云端可依赖 |

### 内存占用 TOP

| 进程 | 占用 |
|------|------|
| WorkBuddy.exe ×6 | 1.77 GB |
| WPS 灵犀 | 0.20 GB |
| MSPCManager | 0.14 GB |
| 其他 214 个进程 | ~1.0 GB |
| **合计** | **3.10 GB / 3.9 GB** |

### 关键结论

> **本地跑 7B 以上模型不可行**（权重本身需 4-14 GB）。
>
> 这台机器的正确用法是**「调度中枢」而非「算力工场」**——重计算推给云端或 API，本机只做编排、判读与交付。

**三层分工**：

| 层 | 职责 | 具体 |
|---|------|------|
| **本机做** | 内容生产、判读推理、客户交付、EVOS 编排、数据聚合 | 4 核 4G 足够 |
| **云端做** | 大模型推理、批量转写、视频渲染、存储 | 按量付费，零持有成本 |
| **不要做** | 本地模型微调、本地视频渲染、常驻多个 Electron、视频转码农场 | 会 OOM |

## 二、业务拓展建议：按「本机适配度 × 客单价」筛选

### ✅ 优先做（高度适配本机）

#### 1. 算仓服务（决策咨询）· 首推

| 维度 | 评估 |
|------|------|
| 本机需求 | **几乎为零** —— 一次通话 60 分钟 + 判读，全部云端完成 |
| 客单价 | 95 元/次，可上探至 300+ |
| 复购性 | 高（同一人可多次，方法可复用） |
| 启动成本 | 一份流程卡 + 一个落地页 |
| **判断** | **本机约束下的最优起点** |

#### 2. 家史服务（AI 辅助深度访谈）

| 维度 | 评估 |
|------|------|
| 本机需求 | 中等 —— 转写可用云端 API，本机只做编排与校对 |
| 客单价 | 3000-5 万 |
| 关键约束 | **长时音频转写必须走云端**，本地 Whisper 在 4G 上会 OOM |
| 存储需求 | E 盘 146 GB 足够放音视频原件 |
| **判断** | 高客单，但交付周期受本机限制，须严格用云端转写 |

#### 3. 决策工具产品化（软件售卖）

| 维度 | 评估 |
|------|------|
| 本机需求 | 低 —— 纯前端 + API 调用 |
| 客单价 | 一次性 69-199 元，边际成本近零 |
| **判断** | 最适合本机（无重计算） |

### ⚠️ 谨慎做

| 业务 | 风险 | 建议 |
|------|------|------|
| 视频号 / 抖音短视频 | 本机无法渲染，4G 内存跑不动 | **纯云端**，或不做 |
| 音频/播客 | 转写可云端，但剪辑占用内存 | 单条制作，勿批量 |
| 知识付费课程 | 录播课需视频制作 | 用 PPT/文档替代，或外采 |

### ❌ 不建议（超出本机能力）

- 本地大模型微调 / 私有部署
- 批量视频转码农场
- 本地 AI 绘画训练
- 多平台实时群控（需多账号并发，内存不够）

- dispatcher 826 行（四端分发、灌稿、台账、数据回流）

| **P0** | 提案/报价生成器 | 把算仓交付标准化，缩短单次耗时 | ❌ 无 |
| **P1** | 客户需求结构化问卷 | 会前收集五参数初值 | ⚠️ 仅有五参数流程卡 |

## 五、最大化本机价值的三个具体动作

### 动作 1 · 把本机从「工场」改为「中枢」

**具体做法**：
- 所有重计算（转写、渲染、模型推理）改走云端 API
- 本机只保留：内容编排、数据聚合、客户交付、EVOS 引擎
- 释放 1 GB 内存 → 多开 2-3 个浏览器标签不再卡

**收益**：消除 OOM 风险，同时让本机响应速度提升（当前内存占用 97% 是卡顿主因）

### 动作 2 · 建立「一单到底」交付标准化

**具体做法**：把算仓 60 分钟拆成可复用步骤
1. 会前：结构化问卷收五参数初值（AI 生成问卷，10 分钟内发给客户）
2. 会中：按九步流程卡走（已固化）
3. 会后：AI 生成复算记录 + 战绩板登记（已具备能力）

**收益**：单次交付从 3 小时压到 1.5 小时以内，**这是提高 OPC 人效最直接的手段**

### 动作 3 · 用 EVOS 沉淀本机踩坑

**具体做法**：
- 每周日 `python tools/evos.py verify`
- 把新踩坑 `distill` 成规则，重复 2 次后进 `trial`
- 固化规则同步到 `EVOS/skills/`

**收益**：同类错误不复发率提升 = 执行成本持续下降

## 六、资源优化建议（一处有明确收益）

**发现**：C 盘仅剩 12.4 GB（82% 已用），E 盘剩 146 GB。

灵犀数据目录 2.6 GB 中，`python-env` 占 1.3 GB、`portable-git` 417 MB、`portable-node` 105 MB。

| 项 | 建议 | 收益 |
|---|------|------|
| 灵犀历史日志（90 MB） | 归档到 E 盘 | C 盘缓解 |
| `_tmp/` 与 `sandbox-extract-*`（共约 40 MB） | 可清理 | 小 |
| C 盘大文件迁移到 E 盘 | 检查 Downloads/Desktop | **可能释放数 GB** |

> 磁盘不紧张但 C 盘偏紧。若后续做音频/视频处理，**必须把工作目录设在 E 盘**。

## 七、三个月路线图

### 第一个月 · 验证（低资源消耗）

| 周 | 重点 | 本机负载 |
|---|------|---------|
| W1 | 理论体系反方论证 + 重仓区案例补充 | 极低 |
| W2 | 算仓交付 SOP 落地，触达 30 人 | 低 |
| W3 | 完成 1-2 单算仓，沉淀案例 | 低 |
| W4 | 复盘：体系是否值得售卖 | 低 |

> **第一个月不要接家史**——它是高客单但交付重，会立刻撞上本机天花板。

### 第二个月 · 扩展

- 触达面扩大到 100 人，验证获客渠道
- 上线算分表（69 元）作为低门槛入口
- EVOS 跑满一轮完整循环（捕获→固化→回验）
- 开始云端转写链路调研（为家史做准备）

### 第三个月 · 交付升级

- **启动家史服务首单**（此时已有算仓案例做信任凭证）
- 音频转写全部走云端
- 案例沉淀成可授权公开素材
