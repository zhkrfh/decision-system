# 桥接系统（Bridge）

> 建立：2026-10-10
> 目的：让沙箱内的 AI 与沙箱外的系统交互，突破沙箱对服务控制等操作的限制

---

## 为什么建这个

沙箱实测确认以下能力被阻断：

| 能力 | 状态 |
|------|------|
| 管理员权限 | ✓ 可用（IsUserAnAdmin = True） |
| 文件 / 注册表 / 进程 | ✓ 可用 |
| **服务控制（服务启停）** | ✗ **静默阻断**（返回假句柄 + err=0） |
| sc.exe / wmic.exe | ✗ 程序黑名单 |
| PowerShell（从 bash） | ✗ 策略拒绝 |

后果：**Windows Defender 修复、服务启停这类操作我无法完成。**

桥接系统让沙箱外的代理执行这些操作，同时**保留安全边界**。

---

## 核心设计：不建无限制执行器

沙箱的价值在于限制危险操作。如果桥接可以执行任意命令，这层保护就被整个绕开。

**因此采用三级风险分级 + 审批门：**

| 等级 | 动作类型 | 执行方式 |
|------|---------|---------|
| **AUTO** | 只读操作 | 自动执行（仍过白名单校验） |
| **APPROVAL** | 有副作用 | **逐条人工确认**，可预先信任特定动作 |
| **DENY** | 不可逆 / 越权 | **永远拒绝**，只记录 |

### 永不执行的动作（硬编码）

```
delete_file        delete_dir         format_disk
reg_write_hklm     service_control    network_config
install_software   modify_defender    credential_input
account_auth       market_publish
```

**这些无法通过任何参数绕过。** 需要时你手动做。

## 使用方式

### 一次性执行（沙箱外）

在普通 PowerShell / CMD 窗口运行：

```bash
python E:\Workspace\bridge\bridge_agent.py --once
```

### 持续监听（推荐）

```bash
python E:\Workspace\bridge\bridge_agent.py --watch
```

每 3 秒轮询一次 `requests/` 目录。**有副作用的任务会弹窗询问 y/n。**

### 预先信任特定动作（减少确认）

```bash
python E:\Workspace\bridge\bridge_agent.py --watch --trust run_python run_bash
```

### 沙箱内提交任务

```bash
cd /e/Workspace/bridge

# 提交只读任务（AUTO，自动执行）
python bridge.py submit read_file '{"path":"E:\\path\\to\\file.md"}' "读取项目文档"

# 提交有副作用任务（APPROVAL，需确认）
python bridge.py submit write_file '{"path":"E:\\out.md","content":"..."}' "生成报告"

# 查看队列
python bridge.py status

# 查看所有可用动作及风险等级
python bridge.py actions
```

## 可用动作

### AUTO（只读，自动执行）

| 动作 | 参数 | 说明 |
|------|------|------|
| `read_file` | `{"path":"..."}` | 读文本文件（>5MB 拒绝） |
| `list_dir` | `{"path":"..."}` | 列目录 |
| `stat_file` | `{"path":"..."}` | 文件属性 |
| `system_info` | `{}` | 系统/内存/磁盘信息 |
| `get_memory` | `{}` | 内存占用 |
| `get_disk` | `{}` | 磁盘空间 |
| `get_process` | `{"filter":"..."}` | 进程列表 |
| `run_ping` | `{"host":"..."}` | 网络连通性 |

### APPROVAL（有副作用，需确认）

| 动作 | 参数 | 说明 |
|------|------|------|
| `write_file` | `{"path":"...","content":"..."}` | 写文件（敏感路径拒绝） |
| `make_dir` | `{"path":"..."}` | 创建目录 |
| `run_python` | `{"code":"..."}` | 执行 Python（<20KB） |
| `run_bash` | `{"cmd":"..."}` | 执行 bash（<2000 字符） |

### DENY（永不执行）

`delete_file` / `delete_dir` / `format_disk` / `reg_write_hklm` / `service_control` / `network_config` / `install_software` / `modify_defender` / `credential_input` / `account_auth` / `market_publish`

---

## 双重防护

即使动作被标为 AUTO，还有第二道检查：

**敏感路径拦截** —— 涉及 `.env` / `secret` / `credential` / `password` / `token` / `id_rsa` / `auth.json` / `auth-snapshot` 的操作，自动降级为 APPROVAL 或拒绝。

实测验证：
```
submit read_file {"path":"...\\.env"}     → APPROVAL（降级）
submit delete_file {"path":"C:\\test.txt"} → DENY（拒绝）
submit read_file {"path":"正常路径"}        → AUTO
```

## 为什么用文件队列而非网络端口

| 考虑 | 文件队列 | 网络端口 |
|------|---------|---------|
| 可审计 | ✓ 每次任务落盘留痕 | ✗ 请求不留痕 |
| 可中断 | ✓ 停代理即停 | ✗ 需处理连接 |
| 攻击面 | ✓ 无监听端口 | ✗ 可能被扫描 |
| 沙箱阻断 | ✓ 不受影响 | ✗ 监听可能被阻断 |

**审计能力是关键** —— 你能随时看到"沙箱想做什么"，而不是被静默执行。

---

## 仍然需要你亲自做的

即便有桥接，以下操作仍然需要你手动完成：

| 操作 | 原因 |
|------|------|
| Defender 修复 | 需服务控制 + UAC 弹窗，属 `modify_defender`（DENY 类） |
| 服务启停 | `service_control` 是 DENY 类 |
| 账号注册 / 实名 / 绑卡 | `account_auth` 是 DENY 类 |
| 平台授权 / 扫码 | `credential_input` 是 DENY 类 |
| 发布键 | `market_publish` 是 DENY 类 |

**这条边界的意义**：AI 可以操作技术层，但不能代替你做身份承诺。

## 建议

1. **先跑 `--once` 熟悉流程**，确认行为符合预期后再用 `--watch`
2. **`--trust` 只信任确实需要的动作**，别图省事全信任
3. **定期看日志**，了解沙箱在做什么
4. **DENY 类动作别试图绕过** —— 它们存在是有原因的
