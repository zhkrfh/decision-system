# 内容自检工具（M1 补齐的验证能力）

> 四个工具，统一入口：`python tools/opc.py check`
> 纯标准库，无常驻进程，单命令 < 1.3s，峰值内存 < 0.3 MB

---

## 一句话

发布前把最容易出错的环节自动化：**算术复算、口径残留、标题钩子、预测到期**。

---

## 工具一览

| 工具 | 对应需求 | 干什么 | 退出码 |
|------|---------|--------|--------|
| `recalc.py` | A3（最高价值） | 独立复算文中算式并比对声明值 | 有不符则 1 |
| `audit.py` | A4 | 旧值/旧公式残留扫描，三层判定 | 有真问题则 1 |
| `lint.py` | A5/A6 | 标题场景化、开头场景化、AI 标注 | 有高风险则 1 |
| `due.py` | E5 | 到期未登记 → EVOS 捕获队列 | 0 |

## 统一用法

```bash
python tools/opc.py check              # 四项全跑
python tools/opc.py check recalc       # 单项
python tools/opc.py check audit --only residual   # 只看真问题
python tools/opc.py check due scan     # 预测到期（只读）
python tools/opc.py check due capture  # 到期写入 EVOS（会改经验库）

python tools/recalc.py --solve 1.12 8 7.9   # 反推 p = 0.5673
```

## 1. recalc · 算术复算（A3）

**为什么**：每篇发布前手工复算是最易出错的环节。已发生真实事故 ——
v1.8.0 口径迁移后草稿箱残留旧值 52.6。

**能力**
- 识别完整算式链：`S = 0.408×7.5 − 0.592×8.5 = 3.06 − 5.03 = −1.97`
- **跨行链合并**（案例01 写作三行，必须拼接后复算，否则漏检）
- 交叉验证中间段：`3.06 − 5.03` 单独算出也要等于全式
- 乘积型：`R×L = 5.1×7 = 35.7`
- 警戒线自洽：`R×L = 6 < 10` 的判定必须与算得值一致
- 反推 p：`p = (S + C) / (G + C)`，案例01 → `p = 0.5673`

**验收基准**（每次运行自动自检）
```
案例01 反推 p = 0.5673（文中 0.567 ✓）
0.567×8 − 0.433×7.9 = 1.1153 ≈ 1.12 ✓
```

**当前结果**：全库 24 处复算，全部一致。

**两个踩过的坑**（改代码时注意）
1. `normalize()` 把 `×` 转成 `*` 后，正则必须按 `*` 匹配，否则 product 检查全失效
2. 整行含 ≥2 个等号时是算式链，子乘积交由 chain 交叉验证，
   product 须跳过 —— 否则会把同行前半段的数字错配进来（误报）

## 2. audit · 口径一致性（A4）

**核心设计：三层判定。** 本项目有大量**故意保留**的旧稿（大纲明确
"旧稿《连载01》由案例01取代，留档不删"）。不区分就会淹没在误报里。

| 判定 | 含义 | 处理 |
|------|------|------|
| `archived` | 已知归档件中的旧值 | 不删不改 |
| `legitimate` | 文中主动宣告"已废弃"的对照说明 | 合规写法 |
| `residual` | 现行口径区的残留 | **必须处理** |

**检查项**：旧公式 `+0.3×R×L` / 旧值 52.6、45.3、27.4、−0.8 / 旧刻度 0..20 /
案例取值跨文档冲突 / 案例编号与 `content_index.csv` 一致性。

**当前结果**：29 处命中 = 真问题 7 / 合规对照 8 / 归档留痕 14。
7 项真问题**全在索引层**（案例01-05 未登记 content_index、2 个索引项无对应文档），
正文口径无残留。

**调规则时的纪律**
- `RESOLVED_PATTERNS`（修复记录）要严：`✅`、`已修`、`45.3→4.54` 才算
- `LEGIT_MARKERS`（合规声明）要严：**不收**「复算」「旧版」等泛化词 ——
  「按旧版口径复算得 52.6」是在陈述旧值本身，不是宣告废弃，
  收进去会让真实残留逃过审计。**漏报比误报危险。**

## 3. lint · 标题与钩子（A5/A6）

**依据**（大纲「账号级约束」）：公众号进算法推荐时代，
「大基数人群+具体场景痛点」远胜「影子价格理论」。**术语只进正文。**

**规则从真实语料反推**，非凭空设定：
- 好标题：月薪两万的 996 / 烧掉的桥 / 六千公里 / 一份 1.12 分的 offer
- 差标题：职业凯利公式 / 影子价格

**当前结果**：7 项建议复核，0 高风险。
命中项集中在连载01/04（归档旧稿）与内部文档（运营案例拆解）。

**踩过的坑**：`get_hook_text` 遇到 `##` 必须立即 break —— 否则钩子文本
只取到章节标题本身，案例01 这种"2026 年秋招，我手里有这样一个机会"
的开场会被误判为"无具体锚点"。

## 4. due · 预测到期（E5）

```bash
python tools/due.py scan              # 列出到期情况（含临期预警）
python tools/due.py capture --dry     # 预览会捕获什么
python tools/due.py capture           # 实际写入 EVOS
```

**幂等是硬要求**：用 `预测到期未登记#案例号@截止日` 作幂等键。
否则每天跑一次就在经验库堆 N 条重复记录，把库撑爆。

**口径纪律**：EVOS 只优化执行层。本工具只捕获"到期未登记"这一**事实**，
不推断预测是否命中 —— 判定留给作者走 distill。

**当前状态**：案例01 还有 25 天（截止 2026-11-04），未触发捕获。
