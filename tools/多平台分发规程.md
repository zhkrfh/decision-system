# 多平台分发规程 v1.0（一鱼多吃管线）

> 原则：**母版一次写成，四端适配输出，发布不同时挂起**。不把增长交给单一平台的算法。

## 一、母版制度（唯一事实源）

- 每篇内容只有一个母版 md（`连载NN_标题.md`），存正典仓库 `docs/连载/`；
- 母版约定：`# 标题` → `> 引言/边界` → `## 小节` → 段落；边界提示用 `> `；
- 母版定稿（算术复算通过）后，一条命令出全部适配稿：
  ```
  python mp_adapt.py 母版.md all   # 输出到 dist/
  ```

## 二、四端适配矩阵

| 平台 | 形态 | 适配规则 | 发布通道 | 时序 |
|------|------|---------|---------|------|
| 公众号（主阵地） | 完整长文 + 绿底封面 | 素材 HTML（现有版式）+ 灌稿 | draft_add API 全自动 | **首发 T0** |
| 知识星球 | 完整长文（Markdown 直持） | `mp_adapt.py → 通用.html` 或直接母版 md | 知识星球连接器 `create_topic` API，你建星球后直发 | T0 同步 |
| 小报童 | 完整长文 | 同通用 HTML，粘贴进专栏编辑器 | 手动（无 API） | T0+1天（付费专栏节奏） |
| 小红书 | ≤1000 字卡片文 + 封面图 | `mp_adapt.py → 小红书.txt`（自动截断+钩子引回公众号）| 手动粘贴 + 随笔同款封面模板改红签 | T0+1天（错峰） |

## 三、钩子设计（跨端导流，不依赖算法等待）

- 小红书截断处自动加「👇 完整算法拆解见公众号『蔵亥喹荣』」；
- 小红书标签固定：#职业选择 #offer #跳槽 #决策 #职场干货 #个人成长（垂直标签，养账号领域权重）；
- 知识星球主题同步后打标签（`set_topic_tags`），作为沉淀层与失效报告收集口；
- 各端文末统一签名行：蔵亥喹荣 · 把能算的算清楚，把算不清的想明白。

## 四、发布时序逻辑

1. **T0 公众号 + 知识星球同步**：完整内容即刻覆盖两个阵地，不等待单一算法；
2. **T0+1 小红书**：错峰既防同文判定，也让小红书卡片成为次日流量第二波；
3. **T0+1 小报童**：付费订阅者与免费读者内容一致（免费立场），晚一天只作为订阅仪式感；
4. 每篇发布后回填正典仓库"发布记录台账"（平台×链接×日期）。

## 五、算力经济性

- 我的部分全自动：母版定稿 → 一条命令出四端稿 → 公众号/星球直接灌，小红书/小报童只留你 2 分钟粘贴；
- 你的部分：审稿 + 四个"发布键"（小红书/小报童无 API，星球建好后也归我）；
- 预计每篇额外成本：转换 1 次命令 + 你粘贴 2 次 ≈ 5 分钟。
